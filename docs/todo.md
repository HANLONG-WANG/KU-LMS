# 课程 TODO

TODO 按 LMS 课程 ID 管理。同一课程在主页、课程抽屉和扩展弹窗中使用同一份记录。

## 使用

- 更新未打包扩展后，在 Chrome 扩展管理中重新加载 KU-LMS，再刷新 LMS 主页。
- 课程卡片的 `☑` 打开课程 TODO；数字表示未完成数量，`+` 表示可以添加第一项。
- 主页 **TODO** 展示当前课表课程的未完成项与全部未完成数量；“すべて見る”包含其他学期的记录。
- 点击扩展图标，默认打开 TODO。即使没有 LMS 标签页，也能编辑已经登记的课程。“设置”页保留原有扩展设置。
- 点击待办正文编辑；勾选完成；删除后到“回收站”恢复或永久删除。
- 输入会保存为草稿。关闭后可以从“未提交的草稿”恢复；只有收到存储确认才显示保存成功。未收到确认的最后输入仍应保留或复制。
- “本地资料”不自动跟随 LMS 账号切换。共用浏览器时可以新建不同资料并手动选择；新资料打开 LMS 主页后登记当前课程。

## 保存与恢复

TODO 使用扩展的 `chrome.storage.local`，不使用 LMS 的会话缓存。不设过期时间，不因换周、换学期、课程列表变化或退出登录清除。

“备份与恢复”可导出当前资料的课程与待办，不包含密码和登录参数。导入先预览，再合并；相同 ID 的不同内容保留副本。导入前保留全部本地资料的快照，可恢复；恢复时会交换当前数据和快照。

卸载扩展或丢失浏览器配置文件会丢失本地数据，请定期导出到外部文件。首版没有跨设备同步。

## 实现与验证

- `src/background/todo-store.js`：唯一持久化写入端，串行请求、版本冲突、幂等重试、软删除、严格格式校验和导入快照。
- `src/shared/todo-client.js` 与 `todo-ui.js`：共享消息客户端和编辑器。
- `src/content/services/todo.js`：课程目录增量登记、首页一览和抽屉生命周期。
- 存储键：`kuLmsTodosV1`；导入前快照：`kuLmsTodosBeforeImportV1`。不要将这两个键加入课程缓存清理。
- `npm test` 包含 `verify-todo-store.mjs` 和 `verify-todo-ui.mjs`，覆盖并发/冲突、存储失败、重启、草稿、确认丢失后的重试、导入恢复、XSS、主页重绘和设置页隔离。
- 独立 Playwright 浏览器验证过课程卡片、抽屉、弹窗和 360px 窄屏；没有自动重载用户浏览器中已安装的扩展。
